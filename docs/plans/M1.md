## 1. Core design

### 1.1 Two stores

- `useSettings` (Zustand + `persist`, localStorage key `jorgu:settings`, `version: 1` with `migrate`). Holds the **full §13 `Settings` shape with defaults from day one**, so later milestones add behavior, not migrations. M1 only reads/writes `language`, `themeId`, `nightMode`, `layout.*`, `youtube.miniPlayerSize`, `web.bookmarks` (picker entries).
- `useUi` (not persisted): open sheet, header visibility per pane, floating-controls visibility, drag state, `youtubePlaying` (simulated in M1), `needsHistoryEntry`.

### 1.2 Layout engine (the heart of §6.3)

`computeLayout(settings, ui, viewport) → LayoutResult` — a **pure function**, unit-tested without a browser.

Output: a rect (or `hidden`) and a `z` for every mounted surface, plus rects for panes, Dock, divider, pane headers, ⛶ buttons, floating bar, edge strip, YouTube control column, mini player, and open sheet.

It encodes every placement rule in one place:
- `split` / `single`, `splitRatio`, Dock on the driver side, banner strip at top (offline/update) that **pushes** the app area down instead of overlaying it.
- `fullscreenPane`: chosen surface covers the app area; Dock and headers hidden.
- YouTube full screen: player area = app area minus a 72 px control column on the driver side (§6.5).
- Mini player: YouTube playing but not in a visible pane → passenger-side corner, 356×200 or 480×270.
- YouTube pane width ≥ 356 px: divider clamp tightened; if the viewport can't fit it in `split`, YouTube is shown `single` or as mini player (§6.1).
- **Exclusion zone:** the YouTube player rectangle is computed first; every chrome element is placed outside it (see §3).
- `driverSide: 'left'` mirrors by flipping x-coordinates of chrome placement in the engine — not CSS `direction: rtl` (that would also flip text).

### 1.3 Rendering surfaces without re-parenting

- `SurfaceLayer` renders every **mounted** surface exactly once inside one fixed container, as absolutely positioned `div`s with `left/top/width/height/z-index` from `computeLayout`.
- **Stable render order:** surfaces are rendered in a fixed order (sorted by surface id), never reordered — React reordering children calls `insertBefore`, which reloads iframes. Stacking uses `z-index` only.
- Lazy mount: a surface mounts the first time it is assigned, then stays mounted (hidden = `visibility: hidden; pointer-events: none`).
- Surface ids: `dashboard`, `map`, `youtube`, and one id per web instance (see Question 3).
- No animated repositioning in M1 (instant). Weak head-unit GPUs + iframe relayout; easy to add a short transition later behind `prefers-reduced-motion`.

### 1.4 Chrome layer

Separate fixed layer above surfaces (but never over the YouTube player rect): pane headers, ⛶ buttons, divider, Dock, floating bar, edge strip, sheets, banners.

## 3. §3.9 groundwork (binding, built into M1 even though the player arrives in M2)

| Rule | M1 mechanism |
|---|---|
| Nothing over the player | YouTube surface has the highest surface `z`. Its pane reserves a 56 px band above the player for header + ⛶, so they never overlap the player. Sheets are driver-side; if a sheet would intersect the player rect, the engine shrinks the YouTube player area beside the sheet (still ≥ 356 px) while it is open. Banners push the app area down. Drag-to-swap feedback is header-only (no ghost following the finger over the player). No edge strip over YouTube — YouTube full screen uses the control column. |
| Pane ≥ 356 px, mini ≥ 356×200 | Enforced in `splitRatio.ts` and `computeLayout.ts`; unit-tested at 800×480, 1024×600, 1280×720, 1920×720, 932×430 (iPhone 16 Pro Max landscape, with safe-area insets). |
| Singleton | `youtube` surface id is unique; assigning it to the other pane swaps. |
| Referrer-Policy | `public/_headers` + `<meta name="referrer">` + same header in Vite dev/preview server config. Never `noreferrer` (the RMF page also forbids the `noreferrer` feature). |
| Automated overlap check (M2 criterion) | `noOverlap.ts` samples a grid of points across `[data-player-rect]` with `document.elementsFromPoint` and fails if the topmost element isn't the player. Runs in every E2E state from M1 on, against the placeholder. |

Drags use `setPointerCapture`, so pointer events keep flowing to the header/divider while the finger crosses iframes — no transparent capture overlay needed.

## 4. Acceptance criteria → how they are met and tested

| Criterion | Implementation | Test |
|---|---|---|
| **Swap works** | Dock ⇄ and header drag (pointer capture; drop when pointer ends over the other pane's rect) call `swap()`. Assigning a singleton that sits in the other pane swaps. | E2E: both paths swap; probe iframes' load count stays 1 (proves no re-parenting). Unit: store swap + singleton rules. |
| **Resize works** | Divider drag → `splitRatio` clamped 0.30–0.70, snap at 40/50/60 % (±2.5 %), YouTube pane ≥ 356 px. Arrow keys for accessibility. | Unit: clamp/snap table. E2E: drag at 4 viewports, check pane widths; load counts unchanged. |
| **⛶ enters full screen in one tap** | 48 px translucent ⛶ always visible at the pane's top corner nearest the driver (in the reserved band for YouTube). One handler: set `fullscreenPane`, `history.pushState`, `document.documentElement.requestFullscreen()` unless already full screen, `display-mode: fullscreen`, or unsupported. Double-tap header does the same. | E2E: one click → surface covers app area, Dock hidden, `document.fullscreenElement` set (Chromium). |
| **✕ / Back / Esc exit** | Single `exitFullscreen(source)`. ✕ and Esc pop our history entry (`history.back()`); `popstate` performs the exit; `fullscreenchange` with no element also exits layer 1. Re-entrancy guard so the three paths never loop. | E2E: each path exits; URL unchanged; Back doesn't leave the app; layer 1 and layer 2 never disagree. |
| **⇄ switches the full-screen app** | Floating bar ⇄ sets `fullscreenPane` to the other pane (also works in `single`: switches to the hidden pane's app). YouTube full screen has ⇄ in its control column. | E2E: Map full screen → ⇄ → YouTube full screen with control column; no reload. |
| **Assignment persists across reload** | `persist` middleware. `fullscreenPane` restores layer 1 only. Chrome skips Back entries created without a user gesture, so after a reload the history entry is pushed on the first touch. | E2E: change assignment, ratio, layout, driver side, language, theme → reload → same. |
| **Driver side mirrors** | Engine flips chrome x-positions: Dock, ⛶ corners, floating bar, edge strip, control column, sheets; mini player goes to the opposite (passenger) corner. | E2E: compare rects for `right` vs `left`; mirrored within 1 px. |
| **Works with no service worker** | Nothing depends on the SW: settings in localStorage, fonts bundled, SW registration wrapped in a feature check. | E2E: run the full suite with service workers blocked (`serviceWorkers: 'block'`). |
| **PWA installs in Chrome** | `vite-plugin-pwa`: manifest (`name` JorGu, `display: fullscreen`, `display_override: ['fullscreen','standalone']`, `orientation: landscape`, `lang: en`, icons 192/512 + maskable), SW precaches app shell + fonts only, `navigateFallbackDenylist: [/^\/api\//]`, no runtime caching of Google/YouTube/embedded sites. Update prompt "New version available · Reload" (user tap only). Offline banner. | E2E on `npm run preview`: SW activates; CDP `Page.getInstallabilityErrors` returns `[]`. Real install on your device: you check. |

Also in M1 (not in the criteria list but in scope): six themes as CSS custom properties with original palettes, each unit-tested for WCAG AA (text 4.5:1, UI/accent 3:1); en/th switch with English fallback; App Picker; Settings sheet with Reset settings.

## 6. Questions / ambiguities

Each has a proposed default. "Approve" = accept all defaults.

1. **Spec location.** Moved from the repo root to `docs/SPEC.md`. *Done.*
2. **Repo location + git.** *Decided: stay in OneDrive.* Git repo initialised and pushed to `github.com/polxvii/JorGU` (`main`). Risk accepted: OneDrive syncs `node_modules` (tens of thousands of files) and may lock files during install/build. If `npm install` or builds fail with `EBUSY`/`EPERM`, pause OneDrive sync and retry, then report.
3. **Web instance identity.** §13 `AppRef` for web is `{kind:'web'; url}` with no id. If both panes hold web and you swap, surfaces keyed by pane index would swap URLs and reload both iframes. Default: add `id: string` to the web `AppRef` (small extension to §13).
4. **Dock ⌂ button** isn't defined. Default: put Dashboard in the focused pane (same as voice "หน้าหลัก").
5. **Focused pane** isn't defined. Default: last pane touched. Taps inside a cross-origin iframe are detected via `window` `blur` + `document.activeElement === iframe`.
6. **`single` layout** — which pane shows? Default: the focused pane; the other stays assigned for toggling back.
7. **Night mode in the UI.** Six HUD themes are all dark-styled; §12.2 says night mode drives the map `colorScheme` but not what it does to the UI. Default: themes are dark; night mode only switches the map scheme (M4) and slightly dims accent/text tokens.
8. **Sheets over a playing YouTube** (e.g. App Picker during YouTube full screen). Default: sheet docks on the driver side and the player shrinks beside it while open (still ≥ 356 px), never covered.
9. **YouTube pane top band.** 56 px reserved above the player for header + ⛶ (header auto-hide can't apply over the player). Costs vertical space at 480 px height. OK?
10. **Thai copy.** I'll write `th.ts`; it needs a native-speaker review before release.
11. **TypeScript 7.0** (native compiler) is current. If lint/tooling doesn't support it yet, I'll pin the latest 5.x/6.x and tell you.
12. **App icon.** I'll draw a simple original SVG mark. Send your own if you have one.
13. **Host app and screen.** *Decided: CarTV.* Screen resolution: M0 probe will measure it.
14. **Cloudflare Workers vs Pages.** *Decided: Workers*, free `jorgu.<subdomain>.workers.dev` name. Default was: Workers with static assets. Cloudflare's own migration guide says Workers has "a distinctly broader set of features" and supports `_headers` / `_redirects` natively. Pages' one advantage here: custom domains whose DNS is not on Cloudflare (not needed with `*.workers.dev`).
15. **How I publish.** *Decided: GitHub + Workers Builds.* Default was: GitHub repo + Cloudflare Workers Builds, so each push to `main` deploys and other branches get preview URLs. I push only after you approve a milestone. Alternative: you run `npx wrangler login` once and I deploy from this machine with `npx wrangler deploy`. Either way, needs Q2 (git) settled first.
